# Implementation Plan: TS-04 — Create Frontend-Only Reports Page with Mock Table Data

---

### 1. Story Summary

Create a Reports page at `/reports` that displays a single table with five hardcoded mock report records. The page is accessible from the dashboard sidebar navigation and shows columns for Report Name, Type, Generated By, Generated Date, and Status — with visually distinct status badges (Completed/Pending/Failed). No backend integration, filtering, pagination, or extra widgets are included.

### 2. Source of Truth

This plan is based on `docs/ai/stories/TS-04/spec.md` (structured specification for TS-04, JIRA key: TS-04, type: Feature, priority: Medium).

### 3. Technical Understanding

The implementation involves three coordinated changes:

1. **New page component** (`src/pages/ReportsPage.tsx`) — a `React.FC` with an inline `Report` interface, a static `mockReports` array, a co-located `StatusBadge` helper component, and a semantic HTML table.
2. **Route registration** (`src/App.tsx`) — add a `<Route path="/reports">` wrapped with `<ProtectedRoute>` and `<DashboardLayout>`, matching the existing pattern for `/dashboard` and `/settings`.
3. **Sidebar navigation update** (`src/components/DashboardLayout.tsx`) — add an `onClick` handler to the Reports `NavItem` to navigate to `/reports` using the already-available `useNavigate` hook.

Key conventions from `project-context.md` that apply:
- Components use `React.FC` type annotation and `export default`.
- Pages follow `*Page.tsx` naming in `src/pages/`.
- Helper components used by only one parent are co-located in the same file.
- Tailwind CSS utility classes exclusively — no inline styles or custom CSS.
- Dark theme palette: `bg-slate-900/40`, `border-slate-800`, `text-white`, `text-slate-400`, `text-slate-200`, emerald/amber/rose for status.
- Import ordering: external libraries first, then internal.
- No `any` types, no `console.log`, files under ~150 lines.
- Config files (`vite.config.ts`, `tsconfig*.json`, `eslint.config.js`, `tailwind.config.js`) must NOT be modified.

The existing `NavItem` component already accepts an optional `onClick` prop (established in TS-03), so no changes to `NavItem` itself are needed.
